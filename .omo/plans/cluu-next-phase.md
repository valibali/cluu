# cluu-next-phase - Work Plan

## TL;DR (For humans)

**What you'll get:** CLUU goes from "boots, shell, edit, micropython" to a genuinely usable hobby OS: it fetches webpages (DHCP, DNS, TCP/UDP sockets, wget), has a real TUI framework (libtui — Elm architecture, diff renderer, components), runs a scriptable emacs/nvim-class editor (MicroPython plugins with scoped capabilities), and ships 20 usable apps across 5 tiers (file manager, pager, IRC client, HTTP server, git, sed, awk, mail, feed reader, htop-rewrite, package manager, and more).

**Why this approach:** Networking changes what the OS *is* (toy → alive). The TUI framework + scriptable editor form a virtuous cycle: the editor is libtui's first real consumer and the capability-scoped plugin host's first real test — if it ships, everything after is cheaper. Static linking is design, not debt (rejected for v1). smoltcp replaces hand-rolled TCP (4-7 weeks, not 12+). The kernel freeze is respected — kernel edits only as freeze exceptions with a named failing userspace test.

**What it will NOT do:** No dynamic linking. No SMP. No GUI. No new kernel syscalls. No runtime ACL. No full bubbletea parity. No mouse-to-apps. No network filesystem.

**Effort:** XL — ~20-30 weeks across 8 waves, 32 todos. Potentially 16-20 with overlap (networking and terminal fixes run in parallel).
**Risk:** Medium — TCP is the classic trap (smoltcp + 3-week pivot trigger mitigates). MicroPython as long-lived subprocess is unproven (feasibility spike de-risks). Editor raw-mode under cluuterm is unverified (verification step gates libtui work).
**Decisions to sanity-check:** (1) smoltcp over DIY TCP, (2) child process + pipe IPC for editor plugins (protocol IS the scope), (3) ANSI-first libtui (SHM deferred), (4) tiered app priority (essentials → network → dev → TUI → system), (5) 256-color now, truecolor deferred, (6) all commits conditional on explicit user request.

## Scope
### Must have

- **C1 Phase 3**: `poll()`/`select()` for pipes, TTYs, `/dev` pseudo-files. Compiler warnings <5. H9/H10 overflow counters in `/proc`. Soak test: 1000× `cat|grep|head` with bounded memory + no orphans.
- **C2 Phase 5**: virtio-net driver on `virtio-core`. `netd` service wrapping smoltcp poll loop. DHCP client. ARP table. `ping 10.0.2.2` (QEMU gateway) replies. BSD socket API (`socket`, `bind`, `connect`, `listen`, `accept`, `send`, `recv`) for TCP + UDP. DNS resolution. `wget http://10.0.2.2/` fetches + prints a page (host-side HTTP server started by harness).
- **C3 Terminal fixes**: ANSI parser CSI param cap lifted from 4 to 16+. 256-color SGR (`38;5;n`, `48;5;n`) — truecolor (`38;2;r;g;b`) DEFERRED (needs cell-format change, no concrete consumer). Alt-screen buffer (`CSI ?1049h/l`) in cluuterm. Bold/underline/reverse attr rendering in packed u64 cell. `Attr` struct extended with `underline: bool, reverse: bool`. cluuterm palette expanded to xterm-256 indices 16-255.
- **C4 libtui v0**: New `userspace/libtui/` crate. Elm MVU runtime (`Model`/`Update`/`View`/`Cmd` traits, `Program` event loop, `Batch`/`Sequence`). ANSI-path cell-buffer diff renderer with dirty tracking. Input decoder (arrows, Home/End/Delete/PgUp/Dn, modifiers, Esc disambiguation — extracted from `edit/src/input.rs`). Three components: `viewport` (scrollable), `textinput` (single-line), `list` (filterable, paginated). Minimal styling (fg/bg/bold/underline, box-drawing borders). Targets ANSI/CSI through cluuterm/pts (hybrid: SHM backend deferred).
- **C5 Scriptable editor**: Upgrade `userspace/edit/` to libtui render loop. Spawn one MicroPython child process per editor session via pipe IPC. Editor exposes scoped plugin API: `buffer.read()`, `buffer.insert()`, `buffer.delete()`, `cursor.move()`, `keymap.register()`, `command.register()`, `view.status()`. Plugin manifest (`.py` file header comment) declares callback registrations and metadata only — authority is structural: the plugin process runs under the restricted `edit-plugin` Cluufile (`PROFILE ipc` only, no vfs/net/spawn), NOT edit's envelope. Three built-in plugins as MicroPython scripts: syntax highlighting, auto-indent, status-line mode indicator. SIGWINCH handling via libtui resize event.
- **C6 App ecosystem**: 20 apps across 5 tiers (ping and wget are networking infrastructure from C2, NOT counted in the 20). Tier 1 (essentials): file manager, pager, hexdump, calc, diff. Tier 2 (network): curl-equivalent, IRC client, HTTP server, NTP client. Tier 3 (dev): git-minimal, sed, awk, make-equivalent. Tier 4 (TUI): mail client (IMAP), feed reader (RSS/Atom), notes/wiki (local markdown), markdown viewer. Tier 5 (system): htop-rewrite (libtui), sysmon, package manager. **Pivot impact**: if the UDP-only pivot is triggered (todo 12), TCP-dependent apps (curl, IRC, HTTP, mail, feed) are replaced with UDP-capable alternatives (DNS lookup tool, syslog client, TFTP client, SNTP client, mDNS responder, UDP echo server, port scanner, netcat-UDP) to maintain exactly 20 apps — the count is NOT reduced. Record the revised app list in the pivot decision file.

### Must NOT have (guardrails, anti-slop, scope boundaries)

- **No dynamic linking / shared libraries / dlopen** — rejected for v1. Static = design (capability model feature).
- **No new kernel syscalls** — use `InvokeOp` on existing token-dispatch path (AGENTS.md §2).
- **No runtime ACL / per-call permission checks** — authorization at spawn via envelope + VFS view (AGENTS.md §3). Editor plugin scoping via protocol surface (IPC API = the scope), not runtime checks.
- **No SMP / multi-CPU** — post-v1, 2027. Non-preemptible kernel invariant holds.
- **No GUI / compositor windowing beyond existing TUI** — post-2026.
- **No full bubbletea parity** — no Kitty keyboard protocol, no OSC52 clipboard, no glamour markdown, no `tea.Exec` subprocess, no snapshot testing. libtui v0 is scoped core only.
- **No mouse-to-apps delivery** — deferred sub-project per `cluu-mouse-minimal-then-full` decision.
- **No kernel preemption changes** — non-preemptible invariant is load-bearing (AGENTS.md, `cluu-kernel-non-preemptible-invariant`).
- **No network filesystem** (NFS/SMB).
- **No speculative kernel work** — kernel freeze active through ~2026-10-21 (or Phase 3 completion, whichever is LATER). Kernel edits only as freeze exceptions, unlocked by a named failing userspace test case. Every kernel commit MUST reference that test case in its first line.
- **No `as any` / `@ts-ignore` / `unwrap()` / `panic!()` in new code** — CLUU is audited; rust-best-practices skill applies.

## Verification strategy
> Zero human intervention - all verification is agent-executed.
- Test decision: **tests-after** for infrastructure (poll, networking, terminal fixes); **TDD** for libtui + editor API surface (pure-logic traits, testable in isolation); **harness-based serial/CSI marker verification** for TUI rendering (no manual visual QA — all verification via `MARKER_MODE` + `SENDKEY_SEQUENCE` on COM2 serial capture, per AGENTS.md §8).
- Framework: Python harness is the primary integration test entry point: `python3 -m cluu_harness --case <name> --no-build` (the bash `scripts/harness_run.sh` was retired in git commit `9de6142b` — the `python/README.md` mention of "coexists" is stale). Cases registered in `python/cluu_harness/catalog.py` via `@cluu_case` decorator (NOT a `cases/` directory); markers in `markers.py`; defaults in `case_defaults.py`. For pure-logic unit tests on no_std crates: use `cargo test --manifest-path <crate>/Cargo.toml` on host or extract testable functions to a `#[cfg(test)]` module that compiles on host (std). For QEMU-booted tests: `python3 -m cluu_harness --case <name>` with `MARKER_MODE` and `SENDKEY_SEQUENCE` env vars per the case registration.
- Evidence: `.omo/evidence/task-<N>-cluu-next-phase.<ext>` — serial log captures, test output, screenshots.
- Every todo's acceptance criteria is an exact command or assertion runnable by the executor agent.
- Soak test (Phase 3 exit): register `l2_soak_test` case in `catalog.py`, run via `python3 -m cluu_harness --case l2_soak_test --no-build` — harness injects 1000 pipeline iterations via sendkey loop (Python-driven, no dependency on CLUU shell `for`/`seq`), then checks `/proc/meminfo` bounded + `ps` no orphans via serial markers.

## Commit strategy

- `feat(<scope>): <summary>` for new features
- `fix(<scope>): <summary>` for bug fixes
- `perf(<scope>): <summary>` for performance
- `docs(<scope>): <summary>` for documentation
- `test(<scope>): <summary>` for tests

Scopes: `poll`, `net`, `netd`, `ansi`, `cluuterm`, `libtui`, `edit`, per-app-name.

Every commit message names *why*, not *what* (diff tells what). Kernel commits MUST reference the userspace test case in the first line per roadmap freeze rule.
