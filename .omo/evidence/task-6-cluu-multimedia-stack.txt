## Authority model (AGENTS.md §2, §3, §5, §6)

- Global displayd control endpoint: created by root-procmgr at init, held in
  global_displayd_control_ep. NEVER forwarded to any compositor or descendant.
  NEVER appears in any param_overrides or PARAM set. Root-procmgr is the SOLE
  holder (root-godmode, AGENTS.md §6).
- Per-session scoped displayd endpoint: created at SESSION_CREATE via
  mint_session_displayd_ep(). Root-procmgr retains the RECV capability (stored
  in session_displayd_endpoints) and derives a SEND-only token (IPC_SEND |
  IPC_CALL rights) for installation via PARAM_DISPLAYD_EP.
- Session binaries resolve displayd via PARAM_DISPLAYD_EP, not via global
  registry. subscribe_output("displayd", "main") and lookup_service(
  "displayd:main") return the session-scoped endpoint from
  info.params[PARAM_DISPLAYD_EP] — analogous to the session VFS redirect
  (PARAM_SESSION_VFS_EP, AGENTS.md §5).
- No runtime ACL, no sender_tid interrogation, no sender_identity check in
  the displayd authority path. Authority is possession of the scoped endpoint
  (AGENTS.md §3).
- Session teardown (destroy_session) revokes the per-session displayd RECV
  capability via token_revoke, which also invalidates all derived SEND tokens.

## Design notes

- PARAM_DISPLAYD_EP = slot 19, next after PARAM_SESSION_VFS_EP = slot 18
  (boot.rs). Defined in cluu_wire::spawn (not boot.rs) because the task
  constrains modifications to spawn.rs for the constant. libcluu re-exports
  cluu_wire as `proto`, and cluu_wire re-exports spawn::* — so
  cluu_wire::spawn::PARAM_DISPLAYD_EP and cluu_wire::PARAM_DISPLAYD_EP both
  resolve.
- The per-session endpoint is a SEND-only derived token (IPC_SEND | IPC_CALL
  rights). Root-procmgr retains the RECV capability. When displayd (T7)
  launches, it will be granted the RECV capabilities to service requests.
- The global displayd control endpoint is a separate endpoint created at init.
  It is never derived, never forwarded, never installed in any PARAM set.
  Root-procmgr uses it to broker cross-session display operations on root's
  behalf (AGENTS.md §6 root-godmode).
- Session teardown (destroy_session) calls token_revoke on the per-session
  RECV capability, which transitively invalidates all derived SEND tokens —
  session binaries lose displayd access immediately.
- T7 (displayd launch) will: (1) receive RECV capabilities from
  session_displayd_endpoints, (2) propagate PARAM_DISPLAYD_EP to session
  grandchildren via session-procmgr's elf_spawn.rs (analogous to
  PARAM_SESSION_VFS_EP propagation), (3) service surface_create /
  buffer_acquire / WM requests on the per-session endpoints.
- No unwrap()/panic!/as any in new code (rust-best-practices compliance).
- Matches existing patterns: PARAM_SESSION_VFS_EP resolution in registry.rs,
  param_overrides mechanism in spawn_service_with_env, endpoint_create +
  token_derive for capability minting.
