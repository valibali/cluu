     - Removed `const MAX_MMAP_REGIONS: usize = 64;` (was line 34).

       - `overlaps`: `iter().any(...)` with same overlap predicate.
       - `find_first_fit`: unchanged cursor-scan algorithm; same overlap check.

     - `reset_mmap_state_for_tests()` unchanged: `*table = MmapRegionTable::new()`

       - `mmap_region_table_grows_beyond_64`: inserts 100 page-sized regions

         retrievable via `find_exact`. This was impossible with the fixed
         64-entry array.
       - `find_first_fit_returns_none_when_region_exhausted`: requests a
         mapping larger than the entire 240 MB mmap address space; verifies

         panic.
       - `remove_then_reinsert_does_not_corrupt`: inserts 10 regions, removes

================================================================================
RESIDUAL RISK
================================================================================
- `swap_remove` reorders entries. This does not affect correctness because
  all lookup/overlap/scan operations are order-independent (linear scans over
  the full Vec, not ordered traversal). If a future caller assumes insertion
  order is preserved, it would break — but no current caller does.
- `insert` is O(1) amortized (Vec push), but `remove`/`find_exact`/
  `update_prot_exact`/`overlaps` are O(n). For server workloads with hundreds
  of regions, `find_first_fit` is O(n * range/PAGE_SIZE) which dominates.
  This is the existing algorithm; optimizing it is out of scope (the plan
  says "replace the fixed 64-entry table", not "optimize the scan").
- The 3 new tests do not run under `cargo test --features host-test` (posix
  feature off). They compile under `cargo xtask build` (posix on, target
  build). Running them on-host requires fixing the pre-existing
  posix+host-test SIGSEGV (pthread no_mangle conflicts with host libc),
  which is outside this task's scope.
