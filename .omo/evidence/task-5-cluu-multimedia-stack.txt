## Module separation

### surface.rs — Surface ownership, buffer slot management
- Surface struct: token, width, height, pitch, double-buffered Vec<u32> pixel data,
  front buffer index, position (x, y), z_order, visible, display_w/display_h (scaling),
  destroyed flag, last_content_damage
- Uses cluu_wire::display::SurfaceState::new for validation (non-zero dims, pitch overflow)
- write_buffer / write_pixel / present / displayed_pixels / clipped_scene_rect / destroy
- Normal SHM uses nonvolatile slice copies (copy_from_slice); hardware ordering is backend-owned

### scene.rs — Z-order, visibility, geometry management
- Scene struct: output info, Vec<Surface>, Vec<Overlay>, pending DamageAccumulator
- Surface lifecycle: create_surface, destroy_surface (damage + buffer release)
- Content: write_surface_buffer, present_surface (translates content→scene damage)
- Geometry: move_surface (damage old+new), set_visible (damage on hide/show),
  set_z_order (damage surface + overlapping surfaces), set_display_size (damage old+new)
- Overlays: add_overlay, set_overlay_position, set_overlay_visible
- composite_frame delegates to compose::composite_frame

### damage.rs — Content/scene/backend damage union, coordinate translation
- DamageAccumulator: Vec<Rect> with add, add_all, add_content_damage, merge, take
- add_content_damage: translates content coords → scene coords using surface (x, y) offset
  CRITICAL INVARIANT: offset MUST match composition read offset (documented in module)
- merge_overlapping: O(n^2) merge of overlapping/adjacent rects
- Bounding-box fallback via DamageList::from_rects when >8 rects

### compose.rs — XRGB8888 row-copy, integer nearest scaling, clip, occlusion
- composite_frame: takes pending damage, clears damaged regions, paints surfaces
  back-to-front (z-order), re-applies overlays (always — cursor invariant), returns damage
- XRGB8888 row-copy fast path: copy_from_slice per row, handles pitch != width
- Integer nearest scaling: precomputed ScaleTable (src_x[dst_x] = dst_x * src_w / dst_w),
  no floating point
- Clipping: surfaces partially off-screen (including negative position) composited
  only in visible region
- Occlusion: back-to-front painter's algorithm; higher z-order overwrites lower
- Overlay re-apply: overlays painted unconditionally after all surfaces (cursor invariant
  from cluu-compositor-cursor-clobbered-by-animated-win gotcha)

### backend.rs — Backend trait + MemoryBackend
- Backend trait: output_info, scanout_buffer_mut, flush, try_direct_scanout
- MemoryBackend: Vec<u32> implementing Backend for host tests; pixel() accessor for
  golden-array verification; fill() for test setup

## Damage coordinate invariant

Documented in damage.rs module docs and lib.rs docs:
The offset used to translate content damage to scene damage MUST be the same offset
the composition pass uses to read surface content. If content damage is translated
with (x, y), the compose pass MUST read surface content at (x, y) — otherwise cells
never refresh from SHM and appear "stale until hovered".
Source: cluu-modal-damage-clamps-border-out.md gotcha.

## Overlay/cursor invariant

Overlays are re-applied after every dirty pass in composite_frame — unconditionally,
not gated on a flag. Client content may overwrite overlay cells at any time; overlays
must be repainted every frame regardless of whether they "moved".
Source: cluu-compositor-cursor-clobbered-by-animated-win.md gotcha.

## Design notes

- no_std + alloc: #![cfg_attr(not(any(test, feature = "host-test")), no_std)]
  Tests use std (cfg(test) disables no_std); normal build is no_std + extern crate alloc.
- #![forbid(unsafe_code)] — no unsafe in the pure core.
- Uses cluu_wire::display types: Rect, DamageList, Error, OutputInfo, PixelFormat,
  SurfaceState (validation), NUM_BUFFERS. No external dependencies beyond cluu_wire.
- Surface uses a simple front/back buffer model (front: u8 index). The full
  SurfaceState state machine (acquire/commit/release with seq validation) lives in
  cluu_wire::display and will be used by the IPC layer in T7.
- composition does a full repaint of all visible surfaces each frame. Damaged regions
  are cleared to black first, then surfaces painted back-to-front. The damage tells
  the backend what to flush. Optimization (partial repaint) deferred.
- MemoryBackend buffer is pitch/4 * height u32 words, matching real backend layout.
- No unwrap()/panic!/as any in production code (rust-best-practices compliance).
- ScaleTable precomputes src_x[dst_x] and src_y[dst_y] — integer division, no float.
