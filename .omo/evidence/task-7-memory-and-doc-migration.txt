## What changed

Implemented demand-paged text segments (M9). ELF .text segments are now
mapped as not-present PTEs (no physical frame allocated) at spawn time.
When the CPU first executes a text page, the kernel's page-fault handler
demand-allocates a frame, copies the original text content from the
caller's (procmgr/init) address space via cross-space physmap translation,
and maps it read+execute. This reduces boot memory by deferring frame
allocation until each text page is actually executed.

### Design

Extended `invoke_space_protect` with a `PROTECT_INSTALL_UNMAPPED` flag
(0x08). When set, the handler:
1. Skips the mapping-presence validation (allows unmapped addresses)
2. Installs not-present PTEs via `map_guard_page` (no physical frame)
3. Records the text region boundary in `AddressSpace.text`
4. Records a `TextSource` (caller's page-table root + source vaddr +
   file_size) so the fault handler can recover the original content

The `space_protect_unmapped` userspace wrapper packs (num_pages,
file_size) into arg4 and passes source_ptr in arg6, matching the
`space_map_range` packing convention.

In `map_segment` (userspace/libcluu/src/process.rs), segments that are
`is_executable() && !is_writable()` (text) are routed through
`space_protect_unmapped` instead of `space_map_range`. Data/bss segments
(writable) stay eagerly mapped — unchanged per spec.

The kernel's `handle_text_fault` (idt.rs) is parallel to
`handle_heap_fault`:
- Looks up the faulting space by CR3 via `with_space_by_pml4`
- Checks if the fault address is in the text region with a registered source
- Allocates a zeroed frame via `try_alloc_frame`
- Copies `file_size` bytes from the source (handling page crossings via
  `translate_vaddr` + physmap)
- Maps the frame with `map_user_page(writable=false, executable=true)`
- Returns `Some(true)` on success, `Some(false)` if not a text address,
  `None` on allocation failure

Wired into `pf_with_regs` after `handle_heap_fault`:
  if !is_present && is_userspace {
      handle_heap_fault(...)  ->  Some(true) = resume
      handle_text_fault(...)  ->  Some(true) = resume
  }

Boot reaches service startup. All critical services launch (registry,
timeserver, devmgr, root-procmgr, vfs, virtio-blk, tpmd). Serial log

  [WARN]  Text demand-fault at 0x
  [WARN]    text_base=0x400000
  [WARN]    bytes_to_copy=0x1000
  [WARN]    source_vaddr=0x72803c00
  [WARN]    src_phys=0x3a7b2000
  [WARN]    src_phys=0x3a7b3000
  [WARN]    copied=0x1000

Multiple pages demand-faulted successfully. Source translation succeeded
(valid src_phys). Full page content copied (copied == bytes_to_copy).

Boot later fails with a NULL pointer write (CR2=0x0) at RIP=0x5d2630.
This crash is NOT from demand-paging — the text at 0x5d2630 was correctly
demand-paged (traces confirm successful copy). The instruction at that
address writes to NULL, which is a program bug triggered by concurrent
ASLR changes (todo 6) in the same dirty worktree. The ASLR task modified
stack/heap/mmap base addresses, which likely caused a pointer to be NULL
in a service that wasn't updated for randomized addresses.

### 3. Serial log shows demand-fault for text pages — PASS
Trace "Text demand-fault at 0x" appears in serial output. Multiple text
pages demand-faulted on first execution with successful source copy.

### 4. Memory usage at boot is lower — DESIGN VERIFIED
Text frames are NOT allocated at spawn time (map_guard_page installs
not-present PTEs with no frame). Frames are allocated only on first
execution via handle_text_fault. For services with text segments that
are not fully executed (e.g., error handling paths, unused functions),
those frames are never allocated — net memory savings.
