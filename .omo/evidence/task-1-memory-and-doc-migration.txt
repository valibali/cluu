TASK 1 (C3): MAP_GUARD flag for space_map_range
================================================

SUMMARY
-------
Added MAP_GUARD flag (0x2000) that installs not-present PTEs (no physical
frame allocated) for explicit guard pages anywhere in the address space.
Used by map_stack_with_guard to install an explicit guard page below each
process stack in init/wiring.rs.

CHANGED FILES
-------------
1. userspace/libcluu/src/syscall.rs
   - Added `pub const MAP_GUARD: usize = 0x2000;` alongside MAP_SHARE_PHYS
   - Added 3 unit tests: test_map_guard_flag_value, test_map_guard_flag_no_overlap,
     test_map_guard_flag_distinct_from_perm_bits

2. kernel/src/elf.rs
   - Added `pub(crate) unsafe fn map_guard_page(...)` — walks page table
     hierarchy (allocating intermediate PDPT/PD/PT as needed via
     pmm::alloc_frame_tagged) but does NOT allocate a physical frame for
     the final PTE. Sets PTE to `USER | NO_EXECUTE` (PRESENT clear).
   - teardown_user_pages skips not-present PTEs (verified: line 1318 of
     vmm.rs: `if pte & pte_flags::PRESENT == 0 { continue; }`), so no
     frame is freed on space destruction.

3. kernel/src/syscall/handlers.rs
   - Added `const MAP_GUARD: u32 = 0x2000;` in invoke_space_map_range
   - Added `let map_guard = (flags & MAP_GUARD) != 0;` flag parsing
   - Added MAP_GUARD branch: rejects incompatible flags (MAP_DEVICE,
     MAP_DEVICE_WC, MAP_SHARE_PHYS, MAP_FRAME_TOKEN, MAP_LARGE_PAGES),
     rejects non-zero data_ptr/data_len, calls map_guard_page per page

4. userspace/libcluu/src/process.rs
   - Added `pub fn map_stack_with_guard(...)` — maps guard_pages below
     stack base with MAP_GUARD, then maps the stack normally
   - `map_stack` is now a thin wrapper calling map_stack_with_guard with 0

5. userspace/init/src/wiring.rs
   - Added `const STACK_GUARD_PAGES: usize = 1;`
   - Updated comment to document explicit MAP_GUARD guard page
   - Changed call from map_stack to map_stack_with_guard with STACK_GUARD_PAGES

6. userspace/libcluu/src/lib.rs
   - Added map_stack_with_guard to the `pub use process::{...}` re-export

ADVERSARIAL CLASSES

  checks `if map_device || map_device_wc || map_share_phys || map_frame_token
  || use_large_pages` and returns Err(InvalidArgument). MAP_GUARD is
  mutually exclusive with all frame-allocating flags. Precedence: MAP_GUARD
  is rejected if combined with any frame-allocating flag — no silent
  precedence, explicit error.

- misleading success_output: Build was run from a clean xtask binary

5. No-frame-allocation verification: REASONED FROM CODE.
   In `map_guard_page` (kernel/src/elf.rs):
   - The function calls `pmm::alloc_frame_tagged` ONLY for intermediate page
     tables (PDPT, PD, PT) — these are shared infrastructure, not per-page.
   - The final PTE is set to `pte_flags::USER | pte_flags::NO_EXECUTE` —
     the address field is 0 (no physical frame backing).
   - No `pmm::alloc_frame()` call is made for the data page.
   - `teardown_user_pages` (vmm.rs:1318) skips not-present PTEs:
     `if pte & pte_flags::PRESENT == 0 { continue; }` — no frame freed.
   - pmm_get_stats before/after would show 0 frame delta for MAP_GUARD pages
     (only intermediate table frames are allocated, and those are shared).
