## Changes

### python/cluu_harness/config.py
- Added `cluu_net: bool` field to `HarnessConfig`, reads `CLUU_NET` env var (default False).

### python/cluu_harness/qemu.py
- In `_qemu_args()`, when `cfg.cluu_net` is True, appends:
  `-netdev user,id=net0 -device virtio-net-pci,netdev=net0,vectors=0`
- Note: task spec said `netid=net0` but QEMU uses `netdev=` property to link
  a NIC to a netdev backend. Verified via `qemu-system-x86_64 -device virtio-net-pci,help`.
- `vectors=0` = legacy INTX (no MSI-X), matching virtio-blk pattern.

## IRQ conflict analysis

- virtio-blk: PCI slot 00:02.0, IRQ 11
- virtio-net-pci: at a different PCI slot (QEMU assigns sequentially, likely 00:03.0+)
- No virtio-net driver exists yet, so no `irq_attach` is called for the NIC.
- No IRQ conflict: virtio-blk retains IRQ 11 exclusively.
- The NIC sits idle in PCI config space — QEMU user-mode networking provides
  a NAT gateway at 10.0.2.2 but no driver means no network traffic.
