## Summary

Implemented the POSIX synchronization primitives SDL2's timer and thread
subsystems require: monotonic/realtime clocks, delay, mutex, thread, TLS,
condition signal/broadcast/timed wait. Used the existing kernel futex with
timeout for real timing — no busy wait, no fake success from timeouts.

## Files modified

- userspace/libcluu/src/posix/time.rs
  - Added `delay(ms: u32) -> c_int` — wrapper around the existing
    `timed_sleep_ms` kernel-level timed IPC recv. Sleeps at least `ms`
    milliseconds (lower bound enforced by kernel timer granularity).
    No busy wait.
  - Monotonic/realtime clocks already present (clock_gettime with
    CLOCK_MONOTONIC / CLOCK_REALTIME, both via kernel time query IPC).
    No changes needed — verified correct.

- userspace/libcluu/src/posix/pthread.rs
  - Added `pthread_cond_timedwait(cond, mutex, abstime)` — the key
    missing primitive. Computes remaining ms from CLOCK_REALTIME to
    abstime, calls kernel futex_wait with that timeout. Returns
    ETIMEDOUT if the sequence counter is unchanged after futex_wait
    returns (real timeout), 0 if signalled. No fake success.
  - Added `compute_remaining_ms(now, abs) -> u64` — pure helper that
    computes remaining milliseconds from current time to absolute
    deadline, rounding up. Returns 0 if deadline has passed.
  - Added `pthread_attr_setdetachstate(attr, detachstate)` — validates
    PTHREAD_CREATE_JOINABLE (1) or PTHREAD_CREATE_DETACHED (0), returns
    0 or EINVAL. JOINABLE is the existing default behavior.
  - Added `PTHREAD_CREATE_JOINABLE` (1) and `PTHREAD_CREATE_DETACHED` (0)
    constants matching newlib's sys/_pthreadtypes.h.
  - Added 16 host-test unit tests (see Testing section).

## Design decisions

### SDL generic vs pthread cond

The task suggested choosing SDL's generic cond implementation (mutex +
semaphore) where safer than widening POSIX. Analysis:

- SDL's generic/SDL_syscond.c uses SDL_sem + SDL_mutex. SDL's generic
  SDL_syssem.c uses SDL_mutex + SDL_cond — creating a circular
  dependency unless a real sem or real mutex/cond backs it.
- SDL's pthread/SDL_syssem.c uses POSIX sem_t (sem_init, sem_wait,
  sem_post, sem_timedwait) — would require implementing a full POSIX
  semaphore API, which is MORE POSIX widening than pthread_cond_timedwait.
- CLUU's kernel futex_wait already supports bounded timeouts
  (timeout_ms > 0 = bounded wait). pthread_cond_timedwait is a thin
  wrapper: compute remaining ms, call futex_wait with timeout, check
  sequence counter. Minimal, correct, no new kernel surface.

Decision: implement pthread_cond_timedwait directly (the pthread cond
path SDL expects) rather than pulling in the generic cond + sem chain.
This is the minimal-widening path.

### No new syscalls

All new code uses existing kernel primitives:
- futex_wait(space, addr, expected, timeout_ms) — already supports
  bounded wait (timeout_ms > 0)
- clock_gettime(CLOCK_REALTIME, ...) — already present
- futex_wake — already used by pthread_cond_signal/broadcast

### SDL config (not modified per MUST NOT scope)

SDL_config_cluu.h currently has SDL_THREADS_DISABLED 1 and
SDL_TIMER_DUMMY 1. T15's MUST NOT restricts modifications to
userspace/libcluu/src/posix/ and .omo/evidence/. The SDL config update
to select real backends (SDL_THREAD_PTHREAD, SDL_TIMER_UNIX) will happen
in T16 when SDL gets a real video backend and becomes spawnable inside
CLUU. The POSIX primitives are now available and link-verified.

### SDL sem backend decision

SDL's pthread/SDL_syssem.c uses POSIX sem_t (sem_init, sem_wait,
sem_post, sem_timedwait, sem_getvalue). Implementing full POSIX
semaphores would widen POSIX beyond what SDL's timer/thread contract
requires. Kept generic/SDL_syssem.c (SDL_mutex + SDL_cond based) —
it composes with the real pthread mutex/cond backends and needs no
new POSIX primitives.
